# NonSteamApps

Living-room apps for SteamOS, added to the Steam library with artwork in the style of Steam's own, drawn around each app's own icon. They come from Flathub, run in NonSteamApps' own copy of the Helium browser, come from their project's own releases (KytyPS5 and Lichii), or, for Files, are part of SteamOS, and each is set up for a TV and a controller. Each Steam account gets its own sign-ins. The apps work in Game Mode and Desktop Mode, and NonSteamApps keeps them up to date.

## Features

- **No root, nothing lost on updates.** Apps install into your user Flatpak installation, which SteamOS updates leave alone. An app you already installed, for example through Discover, is used as it is and never uninstalled. The one step that needs your password is opening LocalSend's port when SteamOS's firewall is on, and NonSteamApps asks first.
- **Every Steam account.** Each account on the device gets a shortcut, with artwork for the library, the capsule, the hero banner, the logo and the icon. The Steam overlay is off for each, at every install and update, and the launcher also removes Steam's overlay library before an app starts. The apps sit together in a **NonSteamApps** collection in the library.
- **Each app's own icon.** The library's artwork follows Steam's own look: the app's icon and name on a dark ground in the app's colours, for the capsule, the wide capsule, the hero banner with its logo, and the icon. NonSteamApps draws it on your device around the icon each app ships, taken from the app itself, so the library shows the icons you know; this repository holds only NonSteamApps' own drawings, for an app whose icon cannot be had (see [Artwork](#artwork)).
- **Native, never Proton.** Every app is a native Linux app, so the best Steam Play setting for each is none. Proton is for Windows programs, and the Steam Linux Runtime's container hides Flatpak and SteamOS's own apps, so either would stop an app starting. Every install and update removes a compatibility tool forced on an app under **Properties → Compatibility**, by you or by Steam.
- **Separate sign-ins.** Each Steam account has its own data in every app except LocalSend, ProtonUp-Qt, Protontricks, Winetricks, Bottles and Files, which have no sign-in, so their settings are shared (see [Several Steam accounts](#several-steam-accounts)).
- **Console-ready browser apps.** Helium, the streaming apps, ProtonDB, SteamDB, Nexus Mods, Proton Mail and Proton Calendar open without first-run pages, prompts or a "Restore pages?" bubble after Steam closes them. The arrow keys move between links and buttons, the interface is dark, and in Game Mode pages are scaled for the TV (see [Helium apps](#helium-apps)).
- **Private by default.** Helium blocks ads and trackers with its built-in uBlock Origin. NonSteamApps' Helium profiles also send Global Privacy Control and keep no crash reports (see [Privacy, security and ad blocking](#privacy-security-and-ad-blocking)).
- **Out of friends' sight.** While a non-Steam game runs, Steam shows friends "In non-Steam game" with its name, and its **Mark as Private** does not work for non-Steam games. So while an app Steam started runs, NonSteamApps makes your Steam account Invisible, and sets back your status, Online or Away, when the last app closes. Friends see you offline meanwhile; chat still works (see `INVISIBLE_WHILE_RUNNING` under [Configuration](#configuration)).
- **Sign-ins in Game Mode.** In Game Mode, Steam's own browser opens apps' links, and it cannot hand a sign-in back to an app. Element's and Bitwarden's sign-in pages and links therefore open in Helium, in front of the app, and the sign-in returns to the app.
- **Controller layouts.** Every app gets a controller layout of NonSteamApps' own: YouTube, Browser, Element, Signal, Discord, Files, Jellyfin, VLC, LocalSend, Minecraft, Emulator, Bottles, Tools or Bitwarden. In the Helium apps, Element, Signal, Discord, Files, Jellyfin, VLC, LocalSend and Bitwarden, holding **Menu** quits; in YouTube, holding **View** reloads; in Eden, Eden-NX2, Lichii, KytyPS5 and Bottles, holding **View** gives a pointer for their windows. A layout you pick yourself stays until you run the installer again.
- **Konsole on the taskbar.** Installing pins SteamOS's terminal, Konsole, to Desktop Mode's taskbar, once: taken off, it stays off, and uninstalling NonSteamApps takes it off only if NonSteamApps put it there.
- **Install, or update.** Running the installer installs every app and sets each up afresh; `nonsteamapps update` brings NonSteamApps and your apps up to date and keeps everything as you set it (see [Install again, or update](#install-again-or-update)). A weekly timer updates the apps NonSteamApps installed, Helium included.

## Requirements

- SteamOS 3, or another Linux system with Steam and Flatpak
- Python 3.8 or newer, `flatpak`, `tar` and `xz`, `gpg` to check Helium's signature, and `curl` to download the installer; all are included with SteamOS
- An internet connection. The first install of each app also downloads its Flatpak runtime or Helium, which takes a while.
- For Eden-NX2, which is built on the device: about 2 GB free, and 4 GB more the first time, for Flathub's KDE SDK (a 1.2 GB download). A build took 19 minutes on four processor cores in testing, and takes longer on fewer.

## Install

In Desktop Mode, open Konsole and run:

```bash
curl -fsSL https://raw.githubusercontent.com/Jadocee/NonSteamApps/main/install.sh | bash
```

This installs every app in the table above. To choose, name them:

```bash
curl -fsSL https://raw.githubusercontent.com/Jadocee/NonSteamApps/main/install.sh | bash -s -- youtube jellyfin
```

From a clone, run `./install.sh [APP...]`. Steam must be closed while its library is changed, so the installer offers to close Steam and starts it again afterwards. It cannot do that from Game Mode.

| Option | Effect |
| --- | --- |
| `--steam-user all\|auto\|ID` | Steam accounts that get shortcuts: all (default), the most recent sign-in, or one account |
| `--no-steam` | Leave the Steam library alone |
| `--no-restart-steam` | Leave Steam closed afterwards |
| `--no-auto-update` | Do not install the weekly update timer |
| `--helium-archive FILE` | Install Helium from a downloaded release archive, with its `.asc` signature beside it |
| `--kytyps5-archive FILE` | Install KytyPS5 from a downloaded Linux build, named as its releases name them; it is checked against GitHub unless `--skip-verify` is given |
| `--lichii-archive FILE` | Install Lichii from a downloaded `lichii-linux-x86_64-pgo.AppImage`, found among its recent releases by its SHA-256; with `--skip-verify`, it is installed unchecked |
| `--eden-nx2-commit COMMIT` | Build Eden-NX2 from this commit of its source, all 40 characters of it, rather than the newest on its branch |
| `--skip-verify` | Install Helium without checking its signature, or KytyPS5 or Lichii without checking them against GitHub (not recommended) |
| `-y`, `--yes` / `-q`, `--quiet` | Answer yes to questions / print only warnings and errors |

### Install again, or update

Run the installer again to install every app afresh, or `nonsteamapps update` to bring what you have up to date as it is:

| | Installer (`nonsteamapps install`) | `nonsteamapps update` |
| --- | --- | --- |
| Apps | Every app, or the ones you name; an app you removed comes back | Only the apps you have |
| NonSteamApps itself | The installer's version | The latest, from where you installed it: GitHub, or your clone |
| Steam shortcuts | Name, launch options and icon set back to NonSteamApps' | Kept as you changed them; only shortcuts already there are refreshed |
| Artwork | NonSteamApps', drawn again around each app's own icon | NonSteamApps' own is renewed, and drawn again once an app's icon changes; artwork you chose stays |
| Controller layouts | NonSteamApps' layout, over one you picked | Yours stays; NonSteamApps' is given where none is set |
| Each app's TV settings | Put back, for example VacuumTube's hidden tabs, Prism Launcher's dark theme and Files' profile | Kept as you changed them |
| Steam Play tool, Steam overlay | A forced tool is removed; the overlay is turned off | The same |
| Collection | The apps join it | Left as it is |
| Helium in Desktop Mode | Its menu entry is written again and pinned to the taskbar | Its menu entry, if still there, is written again; the taskbar is left as it is |
| Konsole in Desktop Mode | Pinned to the taskbar the first time; after that, left as you set it | The same |
| Sign-ins, app data and `nonsteamapps.conf` | Kept | Kept |

Without app names, the installer asks first. Steam is closed only while its library changes; `update` leaves it running when no shortcut needs to change.

## Using the apps

Open them from the **NonSteamApps** collection or **Library → Non-Steam**, in Game Mode or in the Steam client in Desktop Mode. To quit, use the app's own exit, or press the Steam button and choose **Exit game**. In the Helium apps, Element, Signal, Discord, Files, Jellyfin, LocalSend, Bitwarden and VLC, holding **Menu** for a moment quits too.

- **YouTube:** controllers work out of the box, with NonSteamApps' YouTube layout (below). Press `Ctrl+O`, or open YouTube's settings, for VacuumTube's settings: ad blocking, SponsorBlock categories, DeArrow, dislikes, hiding Shorts, codec filters and more. Each Steam account's VacuumTube starts set up for a TV: full screen without window decorations, no "Continue watching?" prompt, no Shorts, no Shorts or Podcasts tab in the side menu, the time left shown while playing, and HDR allowed. Folders made before version 2.11.0 get the window and tab settings once, on their next start; after that, changes you make in VacuumTube's settings stay. On a TV in Game Mode, VacuumTube is scaled to the 1080p layout YouTube's TV apps are made for (1.25× at 1440p, 2× at 4K), so its settings menu is a readable size. While it is scaled, **Unlock Resolution** stays on: VacuumTube limits videos to the screen size it sees, which the scale reduces, so a 4K TV would otherwise get 1080p. HDR needs an HDR TV, Steam's HDR setting turned on, and VacuumTube running on Wayland; if colours look washed out on a screen without HDR, turn off **Wayland HDR** in VacuumTube's settings. To cast from a phone, choose the device in the YouTube app on the same network. In Game Mode, VacuumTube turns Chromium's sandbox off; `GAME_MODE_SANDBOX=1` keeps it on (see [Configuration](#configuration)).
  - **Skipping segments:** SponsorBlock skips sponsors, unpaid and self-promotion, reminders to like or subscribe, intermissions and intro animations, end cards and credits, previews and recaps, and hooks and greetings, with a notice each time. Tangents and jokes are not skipped: VacuumTube calls that category very aggressive. To change what is skipped, open VacuumTube's settings, then **SponsorBlock → Segments to skip**. A segment you jump into plays. Folders made before version 2.21.0 get these settings once, on their next start, except the one for sponsors, which stays as you set it; after that, changes you make stay.
  - **SteamOS theme:** YouTube and VacuumTube's settings take on Game Mode's colours, used as Game Mode uses them: a dark slate background outside videos, a light ring around the highlighted video, the highlighted button or side-menu entry in a lighter grey with white text, and blue for progress and for what is on: the player's progress bar, with the chapters you have watched, the bars on videos you have started, and the switches in VacuumTube's settings. It is a style sheet, `userstyles/nonsteamapps-steamos.css`, which NonSteamApps writes into each account's VacuumTube folder at every start, with VacuumTube's **Enable Userstyles** setting on. To turn the theme off, open VacuumTube's settings, then **Custom CSS**, and switch the sheet off in the list under **Enable Userstyles**; it stays off. To change it, copy it under another name and switch the original off. It changes colours only, so a YouTube update can make part of it stop applying, but cannot disturb the layout.
  - **Refreshing (YouTube layout):** the layout is Steam's Gamepad layout, which VacuumTube reads as a controller, with one addition: holding **View** reloads YouTube, which brings the home screen fresh recommendations. Go back to the home screen first: elsewhere, a reload reloads the page you are on. A short press of **View** still lowers the volume, as in VacuumTube's own controls. With a keyboard, `Ctrl+R` does the same.
- **Element:** set up for a TV and a controller. The arrow keys move between its controls by where they are on screen, Chromium's spatial navigation, which Steam starts Element with (`--enable-spatial-navigation`); in its room list, timeline and menus Element's own arrow-key handling comes first, and in the message box the arrow keys move the cursor. In Game Mode Element fills the screen, and on a TV it is scaled like the Helium apps (`TV_SCALE`). In Game Mode it shows no menu bar, as Signal and Bitwarden do, and elsewhere its bar stays hidden until you press Alt; closing its window or holding **Menu** quits it at once: each Steam account's Element starts with minimising to the tray turned off, as Game Mode has no tray to bring it back from, and without its question before quitting. Folders made before version 2.34.0 get the menu bar and quitting settings once, on their next start.
  - **Controls (Element layout):** the D-pad, or the left stick, moves; **A** selects (Enter), **B** goes back or closes a dialog (Escape), **Y** ticks a box (Space) and **X** shows the on-screen keyboard. **L1** and **R1** go to the previous and next room (Alt+Up and Alt+Down), **View** jumps to a room by name (Ctrl+K) and, held, moves to the next area of the window, such as from the room list to the room (F6), **Menu** opens your user menu, with **All settings** and signing out (Ctrl+\`), and holding **Menu** quits, or, with a link open in Helium, closes Helium: it sends the Browser layout's Ctrl+Shift+W and Ctrl+Shift+Q, which Element takes as its Ctrl+Q. The right stick, or a Steam Deck's right trackpad, moves the pointer, and **R2** clicks.
  - **Signing in, in Game Mode:** matrix.org signs you in on its own website. NonSteamApps opens that page in Helium in front of Element and lets it hand the sign-in back, so once you have signed in, Helium closes and Element carries on. Links you open in Element also open in Helium; holding **Menu** closes it. This needs the Helium app installed. In Desktop Mode, Element uses your usual browser.
- **Signal:** on its first start, link it to Signal on your phone: in the phone app, open **Settings → Linked devices** and scan the code on screen. Each Steam account links its own Signal. As with Element, the arrow keys move between its controls by where they are on screen, it fills the screen in Game Mode and is scaled for a TV, and closing its window quits it. In Game Mode it shows no menu bar: NonSteamApps stands in for a desktop's global menu while it runs, as for Bitwarden, and the layout reaches what the menu holds. See [How Signal keeps its data](#how-signal-keeps-its-data).
  - **Controls (Signal layout):** as Element's for moving, **A**, **B**, **Y** and **X**; **L1** and **R1** go to the previous and next chat (Alt+Up and Alt+Down), **View** searches (Ctrl+F) and, held, moves to the next section of the window (Ctrl+T), **Menu** opens the settings (Ctrl+,), and holding **Menu** quits (Ctrl+Q).
- **Discord:** sign in once for each Steam account: scan the QR code on its sign-in screen with the Discord app on your phone, or type your email address and password with the on-screen keyboard (**X**). As with Element and Signal, the arrow keys move between its controls by where they are on screen (`--enable-spatial-navigation`), and on a TV in Game Mode it is scaled like the Helium apps (`TV_SCALE`) and fills the screen.
  - **Controls (Discord layout):** as Element's for moving, **A**, **B**, **Y** and **X**; **L1** and **R1** go to the previous and next channel (Alt+Up and Alt+Down), **View** opens the Quick Switcher, which jumps to a server, channel or direct message as you type its name (Ctrl+K), **Menu** opens the settings (Ctrl+,), and holding it quits (Ctrl+Q, Discord's **Exit**).
  - **Quitting:** closing its window quits it, so Steam sees it end. Discord normally hides in the tray, which Game Mode does not have, so each account's Discord starts with **Minimize to Tray** off, and running the installer again turns it off again.
  - **In its sandbox:** Flathub's Discord cannot see your other programs, so it shows no game as your activity, and it reaches no keyring, so it keeps its sign-in unencrypted (see [Protecting your data](#protecting-your-data)). Steam starts it with `--password-store=basic`, so that it keeps it the same way in Game Mode and Desktop Mode should a later package reach a keyring.
- **Jellyfin:** starts in its TV layout. Add your server and sign in once for each Steam account. On a TV in Game Mode, it is scaled like the Helium apps (`TV_SCALE`).
  - **Controls (Jellyfin layout):** Jellyfin Desktop's Flatpak cannot reach a controller itself, so the layout sends the keys Jellyfin uses: the D-pad or left stick moves, **A** selects, **B** goes back and, held, home, **Y** searches, **L1** and **R1** rewind and fast forward, **Menu** plays or pauses and, held, quits, **View** goes home, and **X** shows the on-screen keyboard, for your server's address and your sign-in. The right stick, or a Steam Deck's right trackpad, moves the pointer, and R2 clicks.
  - **Sound:** Jellyfin plays stereo until you choose otherwise. For a soundbar or an AV receiver, choose 5.1 or 7.1 under **Channels** in its client settings, and, if your receiver decodes them, AC3 and DTS passthrough.
- **VLC:** press **View** to open a file (Ctrl+O), or hold it for the playlist (Ctrl+L), whose side lists your videos and music, discs, and the network's UPnP media servers and shares. Flathub's VLC can open any folder on the device, an SD card's and USB drives' included.
  - **On a TV:** it starts dark (`--qt-dark-palette`) and, in Game Mode, scaled for the TV (`TV_SCALE`) and filling the screen. Videos play full screen (`--fullscreen`), the window keeps its size whatever the video's (`--no-qt-video-autoresize`), and a video you left part-way carries on where you stopped (`--qt-continue=2`). VLC's first-start question about network access is skipped (`--no-qt-privacy-ask`), which keeps its answer as VLC's default: no album art or other details fetched from the internet; **Tools → Preferences** turns that on.
  - **Each account's VLC:** every Steam account keeps its own settings, recent media and places to carry on from. Started from the applications menu, VLC uses its usual settings.
  - **Controls (VLC layout):** the D-pad moves through VLC's menus, lists and a disc's menus, **A** selects, **B** goes back and leaves full screen, **Y** switches full screen, **X** shows the on-screen keyboard, **L1** and **R1** jump back and forward 10 seconds and, held, to the previous and next item, **Menu** plays or pauses and, held, quits, and **View** opens a file and, held, the playlist. The left stick scrolls, which over a video changes the volume, **R2** clicks where the right stick or right trackpad points, and **L2** opens VLC's menu of everything it can do.
- **Bitwarden:** sign in with your email address and master password; each Steam account keeps its own vault. **X** shows the on-screen keyboard. It starts in its dark theme; running the installer again puts it back.
  - **On a TV:** in Game Mode, Bitwarden fills the screen and shows no menu bar. NonSteamApps stands in for a desktop's global menu while it runs, which Bitwarden's toolkit, Electron, takes as the place for its menu; its keyboard shortcuts still work. In Desktop Mode it keeps its window and menu bar.
  - **Controls (Bitwarden layout):** the D-pad, or the left stick, moves between items and controls by where they are on screen: up and down a list, and left and right between the sidebar, the list and the buttons in a row. **A** selects, opening a link or pressing a button, **B** goes back or closes a dialog, **Y** ticks a box, **X** shows the on-screen keyboard, and **R2** clicks where the right stick or right trackpad points. In a number field, such as the generator's length, up and down change the number; left or right moves on. In place of the menu bar, **Menu** opens the settings, **View** locks the vault, **L1** searches it, **R1** opens the password generator, and holding **Menu** quits. Logging out, syncing by hand, importing and exporting are only in the menu bar, so use Desktop Mode for them.
  - **Quitting:** closing its window quits it, so Steam sees it end. Bitwarden normally keeps running in the tray, which Game Mode does not have.

### On a TV: use its full resolution

In Game Mode, Steam decides the resolution each app runs at. On an external display, its default is usually lower than the TV's own. With the Steam Deck connected to the TV, select an app in your library, then **⚙ → Properties → Shortcut → Maximum Game Resolution → Native**. The setting only appears while an external display is connected. Set it for each app, and for each Steam account. [docs/plans/steam-native-resolution.md](docs/plans/steam-native-resolution.md) describes how automating this is planned.

Game Mode shows a window that is not full screen at its own size, scaled to fit, with black bars, and ignores a request to maximise it. So NonSteamApps opens Files, Prism Launcher, Eden, Eden-NX2, Lichii, ProtonUp-Qt and the Helium browser as large as the screen, and asks for the windows of the Helium browser, Element, Signal and Bitwarden to be full screen; the browser keeps its tabs and address bar, and **F11** leaves full screen in Element and Signal. The site apps already run full screen. A resolution that is not 16:9, such as the Steam Deck's own 1280 × 800, still leaves bars on a 16:9 TV, which **Native** avoids.

Started from the applications menu, VacuumTube, Element, Signal, Discord and VLC use their usual data instead, and Jellyfin uses its default profile. To give every account the same data, set `PROFILE_PER_STEAM_ACCOUNT=0` in `~/.config/nonsteamapps/nonsteamapps.conf`.

## Helium apps

Helium publishes no Flatpak, so NonSteamApps installs its signed release itself. It checks the signature against Helium's public key, keeps the installed version and the one before it in `~/.local/share/nonsteamapps/helium`, and updates it with the other apps. The apps run as follows:

- **Helium** opens as a full browser: maximised in Desktop Mode, and in Game Mode as large as the screen, with its tabs and address bar.
  - **In Desktop Mode:** installing Helium also adds it to the applications menu, under Internet, and to the taskbar, after the launchers already there, for everyday browsing. That entry is Helium's own, with Helium's icon, its **New Window** and **New Incognito Window** actions and the links and files it opens, and it starts the Helium that NonSteamApps installed as a regular desktop browser: in Helium's own profile, `~/.config/net.imput.helium`, apart from the Steam accounts' profiles, and without the TV and controller set-up. Its windows group under that launcher, and `nonsteamapps update` writes the entry again from the Helium installed. Removing Helium takes both away again. If Plasma cannot be reached while installing, as over SSH, pin it from the applications menu instead. A launcher you take off the taskbar stays off until you install again.
- **Prime Video**, **HBO Max**, **Netflix**, **Disney+**, **ProtonDB**, **SteamDB**, **Nexus Mods**, **Proton Mail** and **Proton Calendar** each open their site full screen (kiosk mode), with no address bar or tabs. To leave, hold **Menu**, or press the Steam button and choose **Exit game**.

Each app has its own Helium profile for each Steam account, so signing in to one never signs you in to another. Proton Mail and Proton Calendar share one, because Proton's single sign-on works within one browser profile: signing in to either signs you in to both. With one of them open, opening the other brings it up in front, in the same Helium, while its own Steam shortcut ends at once; **Menu** closes it again. A Proton Calendar profile from before moves into the shared one at the next start of either app or the next install, keeping its sign-in, and removing one of them with `--purge` keeps the shared profile while the other is installed. Before every start, NonSteamApps sets up that profile for a console:

- **No interruptions:** onboarding and welcome pages are marked as seen, and the last session is recorded as closed cleanly. Steam ends apps by signalling them, which would otherwise bring up "Restore pages?".
- **Fewer prompts:** sites cannot ask to send notifications, so Proton Mail's new messages and Proton Calendar's reminders do not pop up; see them on your phone or computer instead. The full-screen apps also turn off translation, password and address saving, and permission prompts.
- **Navigation:** the arrow keys move between links and buttons, as on a TV (Chromium's spatial navigation), and a blue outline marks the one they reach, even on sites that hide it. The outline is for the D-pad and keyboard only: a click with the trackpad shows none, and a video player never gets one. It comes from a small style-only extension of NonSteamApps' own (`share/extensions/focus`), listed in Helium's extensions.
- **Full-screen video:** no "Press Esc to exit full screen" bubble covers the picture; **View** (Escape) leaves full screen.
- **Dark:** Helium's interface is dark, and so are sites that offer a dark theme. In the Helium app, **Settings → Appearance → Mode** switches back to light.
- **Scale:** in Game Mode, pages are scaled so a TV shows a 720p-sized layout (1.5× at 1080p, 3× at 4K). Set `TV_SCALE` to choose a fixed scale.
- **Video:** decoding uses the graphics chip (VA-API), and video plays without waiting for a click.
- **Controllers:** the apps get NonSteamApps' Browser controller layout, which is Steam's Web Browser layout with long presses added. Holding **Menu** quits the app, whatever tabs are open, even when a full-screen site keeps keys to itself: it sends Ctrl+Shift+W and Helium's Exit shortcut, Ctrl+Shift+Q, which NonSteamApps adds to each profile. Holding **L1** or **R1** goes to the previous or next tab. The trackpads work as a mouse and scroll wheel, and **Steam + X** opens the on-screen keyboard. A short press of **L1** or **R1** goes back or forward, and a short press of **Menu** closes a tab. In ProtonDB, links to the Steam store and other sites open in a new tab, so **Menu** brings you back to ProtonDB; Proton Calendar's links to Proton's other apps work the same way. Change the layout under the controller icon on the app's library page.

### Streaming apps: what to expect

- **Widevine:** all four services need Widevine copy protection. Helium downloads it through Helium's services the first time a profile asks for it, and every profile then shares that download. If the first video does not play, close the app and open it again.
- **Picture quality:** on Linux, Widevine runs without hardware protection (level L3), and the services limit browsers like this: Prime Video to standard definition, Netflix to 720p. Disney+ plays, but may limit quality too. HBO Max does not officially support Linux, so it may limit quality, or stop playing altogether. NonSteamApps cannot lift these limits.
- **Helium's services:** they are on by default, because they deliver Widevine and keep the ad blocker's filter lists current. Set `HELIUM_SERVICES=0` to keep Helium from contacting them; the streaming apps then cannot play.

### ProtonDB: your library and report filters

- **Your library:** ProtonDB opens on the list of the games in the Steam library of the account that started it, with each game's rating: its Explore page with **Restrict to library** on. ProtonDB lists every game you own, as it cannot tell which are installed. The first time, the account's dashboard shows for a moment while ProtonDB looks the account up and remembers it; after that, the list opens straight away. No sign-in is needed, but your Steam profile and its **Game details** must be public (Steam → Profile → Edit Profile → Privacy Settings); if they are not, the dashboard stays, saying so. With `PROFILE_PER_STEAM_ACCOUNT=0`, it opens on ProtonDB's home page.
- **Report filters:** open the cog above a game's reports (**Filtering Settings**), set **GPU**, **CPU** and **Distro** (for example AMD, AMD and SteamOS) and tick **Persist Across Site?**. ProtonDB keeps the filters in the browser's own storage, not in cookies, so they stay in that Steam account's ProtonDB profile, and installing again leaves them alone. Matching reports are listed first, with the rest below. ProtonDB also remembers the **Steam Deck** or **PC** tab you last chose on a game page. Reports from a Steam Deck give their distro as SteamOS Holo.

### SteamDB: signing in

- **The first time:** choose **Sign in** on SteamDB, and Steam's sign-in page opens. Sign in there by scanning its QR code with the Steam Mobile app, or with your account name and password. Steam then asks you to confirm signing in to SteamDB, and NonSteamApps confirms it for you when the Steam account signed in is the one that started SteamDB.
- **After that:** whenever SteamDB has signed you out, it starts its sign-in by itself, once each time it starts, and NonSteamApps confirms Steam's page again, so SteamDB opens signed in. If Steam has signed you out too, its sign-in page waits for you.
- **Only SteamDB, only your account:** NonSteamApps confirms Steam's page only when it is asked for steamdb.info, and only for the Steam account that started SteamDB; anything else waits for you. SteamDB receives your public SteamID, never your password.
- **Staying signed out:** sign out on SteamDB's sign-out page, `steamdb.info/signout/`, and it stays signed out until you sign in yourself. With `PROFILE_PER_STEAM_ACCOUNT=0`, the one shared profile belongs to no single account, so SteamDB never signs itself in.

### Nexus Mods: what to expect

- **Signing in:** sign in to your Nexus Mods account from the site's header, in the same window, once for each Steam account; the site then keeps you signed in.
- **Downloads:** **Manual download** saves a mod's file in `~/Downloads`. **Mod manager download** hands it to a mod manager through an `nxm://` link, which needs one installed in Desktop Mode that takes such links; without one it does nothing.
- **Checks:** Nexus Mods sits behind Cloudflare, which now and then asks a visitor to show they are a person. Its checkbox takes a click: point with the right stick or right trackpad and press **R2**.

### Privacy, security and ad blocking

Helium does most of the work, and NonSteamApps keeps its defaults:

- **Ads and trackers:** uBlock Origin is built in. Helium's services keep its filter lists current.
- **Tracking:** third-party cookies are blocked, and WebRTC does not reveal local network addresses. Fingerprinting scripts get slightly randomised answers. Link-auditing pings, page preloading and running in the background are off.
- **Connections:** Helium tries HTTPS first, and warns before it opens a public site over an insecure connection.
- **Updates:** NonSteamApps installs Helium only with a valid signature from Helium's key, updates it every week, and keeps the version before for `nonsteamapps rollback`.

Each new profile also:

- sends [Global Privacy Control](https://globalprivacycontrol.org), which asks sites not to sell or share your data; some laws, such as California's, require sites to honour it;
- keeps crash reports off, so no upload question appears after a crash.

NonSteamApps sets these only when it creates a profile, so a change you make in Helium's settings stays.

Left out on purpose:

| Not added | Why |
| --- | --- |
| Extra extensions, such as ones claiming 1080p on Netflix | Each is more code from another source with access to your sign-ins, to vet and keep updated. The 1080p ones also rely on tricks that the services break without notice. |
| Strict HTTPS-only mode | Helium already prefers HTTPS. Strict mode adds full-page warnings that are awkward to get past with a controller. |
| A fixed secure-DNS provider | Helium already uses DNS over HTTPS when your network's DNS provider supports it. A fixed provider would see every site you visit, and can break home networks that name local devices or filter content. |
| JavaScript without its optimiser | It removes a common route for exploits, but makes the streaming sites' heavy interfaces noticeably slower. |
| Locking the streaming apps to their own sites | Sign-in, payment and playback span many domains that change without notice, so a lock would break them. |
| Changing uBlock Origin's filter lists | Doing it for you would need a system-wide browser policy, which needs root. You can add lists, such as cookie-notice filters, in uBlock Origin's own settings in the Helium app. |

**Ads in ad-supported plans.** uBlock Origin removes ads and trackers from web pages. The ads in the streaming services' ad-supported plans, however, come from the services themselves, alongside the video, so a blocker either cannot remove them or breaks playback; only an ad-free plan does.

## Artwork

Each app's library artwork is drawn in one family, after Steam's own: the app's icon and its name on a dark ground tinted with the app's colours, as a capsule (600 × 900), a wide capsule (920 × 430), a hero banner (3840 × 1240) with a softened echo of the icon, a logo that Steam places on the hero, and the icon. NonSteamApps draws it on your device around each app's own icon, which it takes from the app itself, as a desktop does:

| Apps | Their own icon |
| --- | --- |
| Flathub apps, and Eden-NX2 | The icon the app's Flatpak exports: its scalable one, or its largest of at least 128 pixels |
| Files | The icon SteamOS's icon theme gives Dolphin's applications menu entry |
| Helium | `product_logo_256.png` from Helium's release |
| KytyPS5, Lichii | The icon their project keeps at the release installed, downloaded from GitHub |
| Prime Video, HBO Max, Netflix, Disney+, ProtonDB, SteamDB, Proton Mail, Proton Calendar | The icon the site names in its page or its web app manifest, found by loading the site in a private Helium window with no extensions: a vector icon, or the largest of at least 128 pixels. SteamDB's and Netflix's home pages name no manifest, so NonSteamApps reads theirs, `steamdb.webmanifest` and `site.webmanifest`, as well: Netflix's page names icons of 48 and 64 pixels only, and its manifest one of 512. A site that answers that window with Cloudflare's check that a person is visiting names no icon, and the app keeps NonSteamApps' own, saying so |
| Nexus Mods | Nexus Mods' logo from its own open-source app, `src/NexusMods.App/icon.svg` at release v0.21.1 on GitHub, as its site answers a headless browser with Cloudflare's check |

NonSteamApps' own Helium draws it, headless, from the template `share/artwork/card.html`, at every install and update, before Steam's library is written; it draws an app again only once its icon, or the template, has changed. The drawings are kept in `~/.local/state/nonsteamapps/artwork`, and `nonsteamapps doctor` names each app's icon. An app whose icon cannot be had, or is smaller than 128 pixels, keeps NonSteamApps' own artwork, drawn from the same template around an icon of NonSteamApps' own in the app's colours, so the library stays in one style. So does every app when Helium is not installed, or when `APP_ICONS=0`. Artwork you choose yourself in Steam stays at an update, as before.

Where an app's project publishes artwork for Steam's library itself, those slots use it, taken at the release installed. Of these apps, Lichii's project does, in `dist/branding`: its portrait capsule fills the capsule, its square artwork sits on a softened copy of itself in the wide capsule, and its wordmark, trimmed of empty margins, is the logo over the hero; the hero, which it has none of, is drawn around its icon. The other apps' projects publish none, only Android TV banners for Eden and LocalSend, too small for Steam's slots. Where the project's artwork cannot be had, or is smaller than 256 pixels, NonSteamApps' design takes that slot.

No app's own icon or artwork is in this repository: each is taken on the device from the app, the project or the site it belongs to.

## How Element keeps your sign-in

Element normally protects its stored session secrets with the system keyring. Game Mode has no keyring, and a profile protected by KWallet in Desktop Mode cannot be opened in Game Mode. Steam therefore starts Element with `--password-store=basic --storage-mode=allow-plaintext`.

The session secrets stay in the profile folder, encrypted with a fixed key rather than a password: hidden from casual view, but not protected from software running as your user. In exchange, the same profile works in both modes and Element never stops at a prompt a controller cannot answer. SteamOS's own keyring would be no stronger, as its wallet has no password.

To limit the risk:

- encrypt your home folder (see [Protecting your data](#protecting-your-data));
- set up Element's **Secure Backup** with a recovery key;
- if the device is lost, sign it out from another device under **Settings → Sessions**.

Element started from the applications menu keeps using the keyring.

## How Signal keeps its data

Flathub's Signal keeps the key to its message database in plain text by default (`SIGNAL_PASSWORD_STORE=basic`), because of database-corruption bugs with the encrypted keyrings. Game Mode has no keyring anyway, so each Steam account's Signal always uses this store, and the same profile opens in both modes.

On a first start with this store, Flathub's Signal asks for confirmation, with **No**, which quits, preselected. That is easy to answer wrongly with a controller. NonSteamApps skips the question by creating the account's settings file before the first start, and shows the same note after installing instead.

The key can therefore be read by anyone who can read your files, as can anything in SteamOS's own keyring. Encrypting your home folder protects it (see [Protecting your data](#protecting-your-data)). If the device is lost, unlink it from your phone under **Settings → Linked devices**.

Signal started from the applications menu keeps Flathub's own defaults, including the question.

## Protecting your data

Element, Signal, Discord and Bitwarden keep their data in each Steam account's folders, in your home folder. On SteamOS, a keyring would not protect that data better:

- Game Mode starts no keyring, so apps that look for one find none.
- Desktop Mode's KDE Wallet opens a wallet that SteamOS copies onto every device, and, unless you have given it a password, it opens without one. Anyone with a copy of its files can then read what it holds.

NonSteamApps therefore keeps each app's own store. What does protect the data:

- **Encrypt your home folder.** SteamOS includes `dirlock`, an experimental tool that encrypts your home folder. After it, each start-up stops at a login screen that asks for a PIN or password, with an on-screen keyboard, before Game Mode starts. If the device has a usable TPM, the PIN can be kept there, which limits repeated guesses. Follow [its instructions](https://gitlab.steamos.cloud/holo/dirlock/-/wikis/Enabling-disk-encryption-on-the-Steam-Deck) and back up first:
  - it is set up as root over SSH, with `/usr/lib/steamos/steamos-enable-dirlock` and then `/usr/lib/steamos/steamos-encrypt-home`, and needs free space as large as your home folder plus 2 GB;
  - your files are locked only when the device shuts down, not while it sleeps;
  - `/usr/lib/steamos/steamos-decrypt-home` undoes it.
- **Turn on Steam's lock screen** under **Settings → Security**. A PIN on waking, starting up and switching to Desktop Mode keeps others out of Desktop Mode, where all files can be opened.
- **Bitwarden:** keep its default PIN set-up, and avoid the **Never** lock timeout (see Bitwarden under [Using the apps](#using-the-apps)).
- **Discord:** its sign-in is a token that lets whoever copies it use your account, with no password or two-factor code, and Flathub's Discord keeps it unencrypted, as its sandbox reaches no keyring. Encrypt your home folder, and sign the device out of Discord if its files may have been copied.
- **A lost device:** sign it out of Element from another session, unlink it from Signal on your phone, and sign it out of Discord under **Settings → Devices**, or change your Discord password, which signs out every device.

None of these keeps one Steam account's data from another person who can sign in to the device. Bitwarden asks for its own master password; Element, Signal and Discord have no lock of their own.

## Configuration

`~/.config/nonsteamapps/nonsteamapps.conf` holds eight settings:

| Setting | Default | Effect |
| --- | --- | --- |
| `PROFILE_PER_STEAM_ACCOUNT` | `1` | Separate data for each Steam account (see [Several Steam accounts](#several-steam-accounts)) |
| `STEAM_COLLECTION` | `NonSteamApps` | Name of the Steam collection that holds the apps in each account; leave empty for no collection |
| `APP_ICONS` | `1` | Steam artwork drawn around each app's own icon (see [Artwork](#artwork)); `0` gives every app NonSteamApps' own artwork, from the next install, update or `nonsteamapps steam add` |
| `HELIUM_SERVICES` | `1` | Let Helium use its services, which deliver Widevine for the streaming apps and keep the ad blocker's filter lists current |
| `TV_SCALE` | `auto` | Scale of the Helium apps, YouTube, Element, Signal, Bitwarden, Jellyfin, LocalSend, Prism Launcher, the game lists of Eden, Eden-NX2 and Lichii, KytyPS5's launcher, ProtonUp-Qt, Protontricks, Winetricks and Files: `auto` sizes them for a TV in Game Mode, a number such as `1.5` sets the scale, and `1` turns it off. Replaces `HELIUM_SCALE`, which is still read |
| `GAME_MODE_SANDBOX` | `0` | `1` keeps Chromium's sandbox on for YouTube in Game Mode. Not yet confirmed on a Steam Deck: if YouTube then does not start, set it back to `0` |
| `EDEN_CONSOLE_MODE` | `auto` | Whether the Switch in Eden, Eden-NX2 and Lichii runs docked or handheld: `auto` chooses in Game Mode, docked when Steam runs it at 1000 pixels tall or more and handheld below that, and leaves the emulator's own choice in Desktop Mode; `docked` or `handheld` sets it for every start from Steam; `off` leaves it to the emulator. A game's own **Console Mode**, in its properties, still takes precedence |
| `INVISIBLE_WHILE_RUNNING` | `all` | Keeps the apps out of the status friends see: `all` makes your Steam account Invisible while any app Steam started runs, and sets back your status, Online or Away, when the last one closes; app IDs, such as `eden edennx2 kytyps5`, do it for those apps only; `off` leaves your status alone. An account already Invisible or Offline stays as it is. A status you choose while an app runs is replaced by the one from before when the apps close |

Anything you add to a shortcut's **Launch Options** in Steam after `--steam-account <ID>` is passed to the app, for example `--debug-gpu` for VacuumTube. `nonsteamapps update` keeps it; running the installer again sets the options back.

## Commands

The installer places the `nonsteamapps` command in `~/.local/share/nonsteamapps/bin/`:

```text
nonsteamapps install [APP...]        install every app, or those named, and set them up afresh
nonsteamapps remove APP... [--purge] [--keep-app]
                                     remove apps from Steam and uninstall those NonSteamApps installed;
                                     --purge also deletes their data for every Steam account
nonsteamapps list                    every app, and whether it is installed
nonsteamapps update [--apps-only]    update NonSteamApps and your apps, keeping them as they are;
                                     --apps-only updates only the apps and Helium, as the weekly timer does,
                                     and leaves KytyPS5, Lichii and Eden-NX2 as they are
nonsteamapps rollback [kytyps5|lichii|edennx2]
                                     switch Helium, KytyPS5, Lichii or Eden-NX2 back to the version installed before
nonsteamapps steam add|remove|status [APP...] [--user all|auto|ID]
nonsteamapps doctor                  diagnostics, including each app's last launch log
nonsteamapps uninstall [--purge] [--keep-apps]
nonsteamapps launch APP [--steam-account ID] [--verbose] [-- ARGS]
                                     what Steam runs
```

`./uninstall.sh [--purge]` in this repository does the same as `nonsteamapps uninstall`. Without `--purge`, sign-ins and settings are kept.

## How it works

1. `install.sh` copies the program to `~/.local/share/nonsteamapps`, notes where it came from and runs `nonsteamapps install`. Without app names, that installs every app and puts back NonSteamApps' set-up in the data each already has.
2. Each Flathub app is installed with `flatpak install --user`, unless it is already installed; Winetricks comes with Flathub's Wine, from its `stable` branch (`org.winehq.Wine//stable`). The Helium apps share one signed Helium release, unpacked in `~/.local/share/nonsteamapps/helium`. KytyPS5's newest Linux build comes from its GitHub releases, checked against the size and SHA-256 that GitHub's API records for the file, and is unpacked beside the build before it in `~/.local/share/nonsteamapps/kytyps5`. Lichii's newest PGO AppImage comes from its GitHub prereleases, checked the same way, and is kept beside the build before it in `~/.local/share/nonsteamapps/lichii`. Eden-NX2 is built in Flatpak's build sandbox with Flathub's KDE SDK (`flatpak build-init`, then `flatpak build` for git and CMake), in `~/.local/share/nonsteamapps/eden-nx2`: git fetches the one commit to build, Eden's build downloads the libraries it bundles, each checked against its SHA-512, and ccache keeps what the compiler made for the next build. `flatpak build-finish` gives it Flathub's permissions for Eden, `flatpak build-export` adds it to a repository there that keeps the build before, and Flatpak installs it from that repository, the `nonsteamapps` remote, into the user installation. Files uses the Dolphin SteamOS includes, which NonSteamApps never installs or removes. Helium also gets `~/.local/share/applications/nonsteamapps-helium.desktop`, made from the `helium.desktop` in Helium's release: each `Exec` starts the release's `helium-wrapper` with `--class=nonsteamapps-helium`, the class its name and `StartupWMClass` repeat, and `Icon` is the release's `product_logo_256.png`. It gets a launcher on Plasma's taskbar, added through Plasma's scripting interface on the session bus while Plasma runs, or otherwise in `~/.config/plasma-org.kde.plasma.desktop-appletsrc`, which Plasma reads when Desktop Mode next starts.
3. Each app gets a link in `~/.local/share/nonsteamapps/apps/`, for example `apps/youtube`, pointing at the launcher. Steam's shortcut runs that link with `--steam-account <ID>`. Steam derives the shortcut's app ID from the link and the name, and NonSteamApps writes the shortcut to each account's `shortcuts.vdf`, with the artwork in the account's `grid` folder, drawn first around each app's own icon (see [Artwork](#artwork)). It also adds the app to its collection in the account's collections file (`config/cloudstorage`), which Steam syncs through Steam Cloud. It writes that file the way Steam ROM Manager does, and leaves your other collections alone. Steam is closed while these files change, then started again in a systemd unit of its own, named as Plasma names the apps it starts (`app-steam-<random>.scope`). KDE's screen-sharing prompts then identify it as Steam, not Konsole.
4. When an app starts, the launcher works out the Steam account: the shortcut's, otherwise the most recent sign-in. It then:
   - removes what Steam adds to a game's environment: its overlay library, which stops Helium starting in Game Mode, the Steam Runtime's library paths, and any Proton prefix (`STEAM_COMPAT_DATA_PATH`), which Protontricks would otherwise change whatever game is picked; for Helium, it also replaces Steam's GTK input method (`GTK_IM_MODULE=Steam`) with GTK's simple one, so that the on-screen keyboard types each key once;
   - prepares that account's data (for a Helium app, its profile: preferences, a clean last exit and the shared Widevine folder; for VacuumTube, also the SteamOS theme in its `userstyles` folder);
   - logs to `~/.local/state/nonsteamapps/<app>.log`;
   - unless `INVISIBLE_WHILE_RUNNING` leaves the app out, notes it in `~/.local/state/nonsteamapps/presence.json` and starts a small helper. For the first app to run, the helper sends `steam -ifrunning steam://friends/status/invisible` to the running Steam, the way Steam's own friends menu sets a status, after reading the status the account last chose, `PersonaStateDesired` in its `localconfig.vdf`; an account already Invisible or Offline is left alone. When the app ends, or Steam stops it, the helper takes it off the list and, after the last one, sends the status from before, `online` or `away`;
   - in Game Mode, where Valve's `cecd` reads the TV's remote, starts a helper that ends with the app: it follows `cecd`'s `UserControlPressed` and `UserControlReleased` signals on the session bus, writes each CEC message `cecd` receives to the log, and calls `cecd`'s `Reload` when a button it presses a key for stays pressed for 2 seconds without a repeat or a release (see [Troubleshooting](#troubleshooting));
   - for Element, Signal and Bitwarden in Game Mode, starts two helpers that end with it: one asks for its window to be full screen, which gamescope then sizes to the screen, and one owns `com.canonical.AppMenu.Registrar` on the session bus, which the app may talk to for that run, so that Electron puts the menu there and draws no menu bar. Discord, VLC and Bottles get the first helper only. Where the window manager records a window's state, as gamescope's development version does, the helper asks again for a window that leaves full screen, as VLC's does when a video ends;
   - for Eden and Eden-NX2, starts it with `flatpak run --cwd=<the account's folder>`, on X11 (`--socket=x11 --nosocket=fallback-x11 --env=QT_QPA_PLATFORM=xcb`). Eden keeps everything in a `user` folder in its working folder when there is one, its portable mode, so NonSteamApps first writes that folder's settings, then links its keys, firmware, installed content, mods and shader caches to the emulator's own data. Each start writes the graphics settings into `user/config/qt-config.ini` (Vulkan, and for Eden-NX2 ASTC kept as BC3) and copies Eden's `prod.keys` and `title.keys` into Eden-NX2's own data where its copies are missing or older;
   - for Lichii, does the same as for Eden, in its folder among NonSteamApps' profiles, with Eden's keys and, while Lichii has none of its own, Eden's firmware, and then starts its AppImage there, on X11 (`QT_QPA_PLATFORM=xcb`);
   - for KytyPS5, starts its launcher in the account's folder, in which the build's programs are hard links, so that KytyPS5 keeps its settings and saves there. `$TERMINAL` names NonSteamApps' stand-in, through which the launcher starts a game without a terminal window or a key to press at the end. In Game Mode, both run on X11 (`QT_QPA_PLATFORM=xcb`, `SDL_VIDEO_DRIVER=x11`), and the launcher's and the game's windows carry one name in their window class, which the full-screen helper asks to fill the screen, leaving dialogs at their own size;
   - for Element and Bitwarden in Game Mode, stays as the app's parent, with its own `xdg-open` first on the app's `PATH`. That script sends web links and sign-in callbacks through a pipe in the app's runtime folder, which Flatpak shares with the sandbox. NonSteamApps opens a web link in Helium, which Game Mode shows in front of the app because Steam started both, and starts the app again with a callback, which then reaches the running app;
   - otherwise replaces itself with `flatpak run <app> …` (for Signal, Discord and VLC, `flatpak run --command=env …`, so that the app's own launch script sees the account's folder as its `XDG_CONFIG_HOME`; for ProtonUp-Qt and Protontricks, with `--filesystem` for each folder in Steam's `libraryfolders.vdf`, for that run only; for Winetricks, `flatpak run --command=winetricks org.winehq.Wine`, which opens its menu), with Helium and its console flags, or with Dolphin and its TV profile: its own `XDG_CONFIG_HOME` and `XDG_STATE_HOME`, with Desktop Mode's settings underneath through `XDG_CONFIG_DIRS`.
5. For apps with a controller layout, NonSteamApps finds the layout in Steam's `controller_base/templates` and records it for the shortcut in `steamapps/common/Steam Controller Configs/<ID>/config`, where Steam keeps the layout a user picks. An install puts NonSteamApps' layout back over one you chose, and an update keeps yours. Every install and update also removes any Steam Play tool forced on its shortcuts from `config/config.vdf` (`CompatToolMapping`), as Steam ROM Manager does, keeping a backup, and keeps each shortcut's `AllowOverlay` at 0 in `shortcuts.vdf`. Where SteamOS has Plasma Remote Controllers, which turns the TV's remote into key presses, installs and updates also turn off its controller backends (see [Troubleshooting](#troubleshooting)). The YouTube, Browser, Files, Jellyfin, LocalSend, Minecraft, Emulator, Tools and Bitwarden layouts are NonSteamApps' own: each is made from one of Valve's layouts on the device, written into that folder first, one file per controller type, and removed with the last app that uses it.
6. If firewalld is running, LocalSend's port is opened with `sudo firewall-cmd`, and NonSteamApps records what it opened so that it can close it again.
7. `nonsteamapps update` fetches NonSteamApps again from where the installer came from, runs that version's `install.sh` to copy only the program, and hands over to the new version. That version updates the apps and Helium, then refreshes the shortcuts already there. NonSteamApps notes a fingerprint of each artwork file it puts in Steam's `grid` folders (`~/.local/state/nonsteamapps/artwork.json`), so it renews its own artwork and leaves artwork you chose. Steam is closed only if a shortcut must change.
8. A weekly systemd user timer runs `nonsteamapps update --apps-only`, which updates the apps and Helium but neither NonSteamApps itself, KytyPS5, Lichii, Eden-NX2 nor the Steam library. Discover updates any other Flatpaks.

## Troubleshooting

- **"Steam is running in Game Mode":** switch to Desktop Mode and run the command again.
- **An app does not start:** `nonsteamapps doctor` shows each app's last launch log, and whether a Steam Play tool such as Proton is forced on it; `nonsteamapps launch youtube --verbose` runs it in the terminal.
- **An app stopped starting after you chose Proton or another compatibility tool for it:** run `nonsteamapps steam add <app>`, or untick **Force the use of a specific Steam Play compatibility tool** in its Properties. NonSteamApps' apps run natively.
- **A Helium app stays on Steam's loading screen in Game Mode and cannot be exited** (versions 2.2.0 to 2.8.0): run the installer again to update. Those versions let Steam's overlay library into Helium, which then never starts.
- **After installing, a window asks to share the screen with Konsole** (before version 2.10.1): decline it, then restart Steam from the application menu or run the installer again to update. The installer started Steam again from Konsole, and KDE treats a program started from Konsole as part of Konsole, so Steam's request to capture the screen was shown as Konsole's.
- **In Game Mode, Element's or Bitwarden's sign-in opens in Steam's browser and never comes back:** install Helium with `nonsteamapps install helium`. NonSteamApps opens sign-in pages in it, and the app's log (`nonsteamapps doctor`) says when it is missing.
- **Helium asks whether to open a link with xdg-open after you sign in:** choose **Open**. NonSteamApps allows the sign-in page's own site in advance, but a sign-in that ends on another site, such as your organisation's, asks once.
- **A new Steam account has no shortcuts:** run `nonsteamapps steam add`.
- **YouTube, Files, Prism Launcher, ProtonUp-Qt, Protontricks or Winetricks has Steam's default controls:** run `nonsteamapps steam add youtube files prism protonup protontricks winetricks`. It writes NonSteamApps' layouts again, for example after a Steam update removed them.
- **A tool installed with ProtonUp-Qt is missing from a game's Compatibility list:** restart Steam, which reads its tools when it starts.
- **Protontricks does not list a game:** start the game once from Steam, then open Protontricks again.
- **An account has no NonSteamApps collection:** Steam creates an account's collections file the first time it opens the library. Open Steam with that account once, close it, then run `nonsteamapps steam add`.
- **A Helium update misbehaves:** `nonsteamapps rollback` switches back to the previous version.
- **Eden warns that keys are missing, or its controller does nothing:** see **Eden** under [Using the apps](#using-the-apps). On a Steam Deck, the right trackpad and a press on it dismiss the warning.
- **A press on the trackpad does not click in Eden, Eden-NX2 or KytyPS5, though Steam + R2 does:** before 2.31.0 the Emulator layout left the press as the right stick's click, Valve's binding for it: the press sits on a soft press, which NonSteamApps did not change. Run `nonsteamapps update`, or the installer, to write the corrected layout. With any controller, holding **View** and pressing **A** also clicks; if you picked another layout for the app, choose **Emulator (NonSteamApps)** again.
- **Menu and View do each other's job, such as holding View to quit or holding Menu to reload YouTube:** before 2.34.0 every NonSteamApps layout had the two the other way round, because Steam's layouts name the Menu button (≡) `button_escape` and the View button (⧉) `button_menu`. Run `nonsteamapps update`, or the installer, to write the corrected layouts, which Steam reads again as their revisions went up.
- **Eden-NX2 asks for keys and its window then stops answering in Game Mode:** its **Yes** opens a file chooser that Game Mode may not show. Close it with the Steam button's **Exit game**, install the keys in Eden from Desktop Mode, and start Eden-NX2 again: it takes them. Without keys in Eden, answer **No**.
- **After the TV remote's Home, Assistant or another button for the TV's own menus, Steam's navigation sound keeps playing behind an app:** on current SteamOS, which the Steam Machine runs, Valve's `cecd` reads the remote over HDMI-CEC and holds a key of its virtual keyboard down from the TV's press until the TV's release. For its own menus, a TV can send the press, such as Home's "device root menu", and then show the menu without sending the release, so the key stays down and repeats. Every install and update gives `cecd` its own key mappings without the TV's menus, in `~/.config/cecd/config.d/50-nonsteamapps.toml`, and has it read them again; the arrows, OK, Back, numbers, colour and playback buttons keep working. An update leaves the file as you changed or removed it, and uninstalling removes it. A TV can also leave held a button `cecd` still maps, such as the arrow or OK pressed as its menu opened. So while an app runs in Game Mode, NonSteamApps follows the presses and releases `cecd` reports on the session bus: when a button `cecd` presses a key for stays pressed for 2 seconds, with neither the repeat a TV sends for a held button nor its release, it has `cecd` reload, which lets the key go. A reload also announces the Steam Machine on the HDMI bus again, which some TVs show, and on a TV that sends no repeat for a held button, it ends a hold after 2 seconds. It leaves `cecd` alone where SteamOS's HDMI-CEC setting is off, and never starts it. The app's log, `~/.local/state/nonsteamapps/<app>.log`, lists each message `cecd` receives, as `CEC <seconds> <from>><to>: <bytes>` (`44` is a press, `45` a release), and each key let go. Outside an app, press any button on the remote, which lets the held key go, or run `systemctl --user reload cecd`. To see what your TV sends at any time, run `busctl --user monitor com.steampowered.CecDaemon1` and press the button: a `UserControlPressed` with no `UserControlReleased` after it is a press the TV left held. On SteamOS before SteamOS Manager 26.2, Plasma Remote Controllers read the remote instead, and by default also turned every controller's buttons and left stick into Enter, Ctrl, Shift and arrow keys, so installs and updates turn that off in `~/.config/plasma-remotecontrollersrc` (`EnableJoystick=false`, and `EnableEvdev=false` for versions before 2025), and restart it.
- **Steam's on-screen keyboard types each letter twice in Helium, as on a sign-in page opened for Element:** Game Mode gives games Steam's own input method (`GTK_IM_MODULE=Steam`), which can deliver the same text twice to a Chromium-based program that runs on SteamOS itself, as Helium does. From 2.31.0, Helium starts with GTK's simple input method there instead; the apps in Flatpaks never load Steam's.
- **A game stopped working after a KytyPS5 update:** `nonsteamapps rollback kytyps5` switches back to the build before; your saves stay.
- **Eden-NX2 did not build:** the installer, or `nonsteamapps update`, shows the end of the build's log, and `nonsteamapps doctor` names the log file. A failed build changes nothing installed. A change on Eden-NX2's branch can break its build on Linux, which its author does not test: build an earlier commit with `nonsteamapps install edennx2 --eden-nx2-commit COMMIT`, or try again once the branch has moved. A build that misbehaves can be switched back with `nonsteamapps rollback edennx2`.
- **The library shows NonSteamApps' artwork rather than an app's own icon:** `nonsteamapps doctor` shows, for each app, whether its artwork was drawn around its own icon and which one. The install's output says why an app kept NonSteamApps' artwork, for example a site that named no icon, or one smaller than 128 pixels. Drawing needs Helium: install it with `nonsteamapps install helium`, then run `nonsteamapps steam add`. A site's icon is looked up again at every install and `steam add`.
- **Lichii is not installed, or a build misbehaves:** as for KytyPS5, NonSteamApps installs a build only when GitHub records its SHA-256, and says why it did not. `nonsteamapps rollback lichii` switches back to the build before; your saves stay.
- **KytyPS5 is not installed:** NonSteamApps installs a build only when GitHub records its SHA-256, and says why it did not. Run `nonsteamapps install kytyps5` again later, or install a build you downloaded with `--kytyps5-archive FILE`, which is still checked against GitHub.
- **A streaming app shows a playback error the first time:** close the app and open it again, once Widevine has downloaded. `nonsteamapps doctor` shows whether it has.
- **The picture looks soft on a TV:** see [On a TV](#on-a-tv-use-its-full-resolution).
- **YouTube does not start in Game Mode after setting `GAME_MODE_SANDBOX=1`:** set it back to `0`.
- **Phones and computers cannot see the device in LocalSend:** `nonsteamapps doctor` shows whether the firewall lets port 53317 in. If it does not, run the installer again. If opening the port failed because your account has no password, set one first with `passwd`. Also check that your router does not isolate devices from each other, which guest networks often do.
- **Friends still see an app in your status:** Steam shows the app until the account turns Invisible, a second or two after it starts, and an app started outside Steam is not shown at all. `nonsteamapps doctor` shows the app's log, which says whether the account was made Invisible. If `INVISIBLE_WHILE_RUNNING` names apps, check that it names this one.
- **You stay Invisible after closing the apps:** the status comes back when the last NonSteamApps app closes, so check that none still runs. If the device was switched off or Steam was closed while an app ran, the next app's close sets it back; or choose **Online** in Steam's friends menu.
- **The screen dims, or the device sleeps, during a video:** Game Mode ignores the requests that video apps send to keep the screen on. In Steam's settings, under Display and Power, lengthen or turn off the dimming and sleep timers. Alternatively, use a Decky Loader plugin that pauses them while something plays.
- **Casting from the YouTube app does not find the device:** with the firewall on, casting may be blocked. VacuumTube answers on UDP port 1900 and a TCP port it picks at random each time, so NonSteamApps cannot open a fixed port for it.

## Development

```bash
python3 -m unittest discover -s tests          # apps, Flatpak, Helium (with real signatures), Steam, layouts and command-line flows
shellcheck -x -P SCRIPTDIR install.sh uninstall.sh src/bin/nonsteamapps tests/sandbox.sh tests/fakes/sudo tests/fakes/dolphin src/share/sandbox/xdg-open src/share/kytyps5/terminal tests/containers/*.sh tests/containers/steamos/*.sh
tests/sandbox.sh                               # install.sh, launches through the links Steam runs, uninstall.sh
tools/render-artwork.py [APP...]               # draw assets/artwork/<app> around assets/src/<app>/icon.svg, in a headless Chromium
```

| Path | Purpose |
| --- | --- |
| `install.sh`, `uninstall.sh` | Entry points (work from a clone or through `curl … \| bash`) |
| `src/bin/nonsteamapps` | Launcher: runs the command-line interface, or starts an app when called through its link |
| `src/lib/nonsteamapps/` | Python standard-library package: `apps.py` (the apps), `flatpak.py`, `helium.py` (the signed Helium release), `browser.py` (console profiles and flags), `display.py` (TV scale), `controllers.py` (Steam layouts), `layouts.py` (NonSteamApps' own layouts), `collection.py` (the Steam collection), `compat.py` (Steam Play tools), `steam.py` and `vdf.py` (shortcuts and artwork), `steamclient.py`, `firewall.py` (LocalSend's port), `selfupdate.py` and `net.py` (updating NonSteamApps itself), `links.py` (sign-ins in Game Mode), `x11.py` (full-screen windows in Game Mode), `desktop.py` (Desktop Mode's applications menu and taskbar, Konsole's included), `appmenu.py` (Bitwarden's hidden menu bar), `artwork.py` (artwork drawn around each app's own icon), `builds.py` (builds from GitHub releases), `kyty.py` (KytyPS5's builds and account folders), `lichii.py` (Lichii's AppImages), `cli.py` |
| `src/share/` | Default settings, the update timer, Helium's public signing key (fingerprint `BE67 7C19 89D3 5EAB 2C5F 26C9 3516 01AD 01D6 378E`), Helium's focus extension, ProtonDB's and SteamDB's extensions, KytyPS5's stand-in terminal, VacuumTube's SteamOS theme (`userstyles/`) and the artwork's template (`artwork/card.html`), with the Inter Display font it is set in, cut down to Basic Latin (`artwork/OFL.txt`) |
| `assets/src/<app>/icon.svg`, `assets/artwork/<app>` | NonSteamApps' own icon for each app, and the artwork drawn around it, used where the app's own icon cannot be had |
| `tests/fakes/` | Stand-ins for `flatpak`, `firewall-cmd`, `sudo`, `systemctl` and a headless Chromium's DevTools pipe (`devtools`), used by the tests; `tests/_fakes.py` also builds stand-in Helium, KytyPS5 and Lichii releases |
| `compose.yaml`, `tests/containers/` | The test containers: an image like CI's (`ci/`), a SteamOS image (`steamos/`), and the scripts their services run |

To add an app:

1. Add an `App` to `apps.py` with its Flathub ID, arguments and per-account data.
2. Draw its icon in `assets/src/<app>/icon.svg`, give it its colours in `artwork.COLOURS`, and run `tools/render-artwork.py <app>`.
3. Extend the tests.

### In containers

`compose.yaml` runs the checks above in containers, with others that need more than a clone. Run them from the repository's root with Docker Compose; each service mounts the repository read-only:

| Service | What it checks |
| --- | --- |
| `unit`, `unit-py38` | The unit tests on Ubuntu 24.04's Python, as CI runs them, and on Python 3.8, the oldest NonSteamApps supports |
| `lint` | ShellCheck, pyflakes and a compile of the artwork tool |
| `sandbox` | `tests/sandbox.sh` |
| `steamos` | The unit tests and `tests/sandbox.sh` on SteamOS's own packages: its Python, GnuPG, D-Bus, Xvfb and Chromium |
| `flathub` | Flathub still has every Flatpak NonSteamApps installs, under the ID and branch it installs |
| `artwork` | Every app's artwork draws, in a copy of the repository |
| `keyring` | SteamOS's KDE Wallet still starts only in Desktop Mode, and its wallet still opens without a password, as [Protecting your data](#protecting-your-data) says |
| `e2e` | A real install of LocalSend from Flathub with SteamOS's flatpak, a start in its sandbox, and its removal |

```bash
docker compose run --rm steamos                # one service; the first run builds its image
STEAMOS=3.9 docker compose run --rm steamos    # on another SteamOS release
docker compose up --abort-on-container-failure # every service but e2e, at once; a failure stops the rest
```

The SteamOS image is installed only from one SteamOS release's repositories, those Steam Machines and Steam Decks update from; 3.8 unless `STEAMOS` names another. It has no Steam, gamescope or Game Mode. `flathub` and `e2e` need the internet, and `e2e` needs about 2 GB for LocalSend and its runtime, which it downloads afresh each time.
